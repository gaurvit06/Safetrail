# Decisions

Deviations from SPEC.md and why. Newest last.

1. **Repo lives at a short path** (`C:\Users\gaurv\safetrail`). Windows' 260-character path limit broke Python DLL loading (and would break `node_modules`) inside the long scratch folder.
2. **Times are unix epoch seconds (float, UTC)** everywhere: database, API and events. Simpler than ISO strings and identical in Python and JavaScript.
3. **Pure-Python geometry** (`backend/app/geo.py`) instead of shapely, and **incremental clustering** (an SOS joins an open incident on the same route within `CLUSTER_EPS_M` and 30 minutes; nearby incidents merge) instead of scikit-learn DBSCAN. Same result as DBSCAN with `min_samples=2` for the small numbers here, and no heavy dependencies on Python 3.14.
4. **Advisory and template languages start with English and Hindi** (`ADVISORY_LANGS=en,hi`). More languages are a config change once their templates exist in `backend/seed/templates/`.
5. **The hall route coordinates are placeholders.** Stage scenarios ("Landslide here", "Crowd surge") place zones and simulated people around the judges' live positions, so the demo works anywhere. Replace `backend/seed/routes/hall.json` with the real venue when possible.
6. **SMS parsing (5.8.6)** was first in the cut order and is now built (see 24).
7. **`.env` is read from the repo root**, then `backend/.env` (overrides), so `.env.example` sits at the root as in SPEC.md Section 11.
8. **Signing keys** are generated into `backend/keys/` on first run when `PASS_SIGNING_KEY` / `LOG_SIGNING_KEY` are empty. That folder is git-ignored.
9. **Map tiles are OpenStreetMap raster tiles** (CARTO basemaps now require an API key). Light use only, never bulk-prefetched; viewed tiles are cached by the service worker. Offline, the route, zones and help points still draw as GeoJSON on a plain background. The projector uses a dimmed copy.
10. **No shadcn/ui generator:** small Tailwind components in `frontend/src/components/ui.tsx` instead, to avoid a CLI step.
11. **Hold-to-SOS completes on a timer**, not on animation frames, so it can't get stuck when the browser throttles frames.
12. **`db.init_db()` adds missing columns** to an existing SQLite database (forward-only), so pulling an update never breaks a local database.
13. **Demo location mode** (tourist sheet → "Demo: tap the map") moves your dot by tapping the map, for rehearsals and indoor demos where GPS is poor. It's clearly labelled on screen.
14. **Weather only suggests zones.** The responder weather panel's "Draw a zone here" pre-fills the zone tool (custom kind, 250 m circle, 6 h expiry, the warning as the note). The officer reviews and publishes; weather never publishes a zone by itself.
15. **`prune_client.probe()`** makes the raw diagnostic calls for `scripts/prune_check.py` (no retry, no logging), so the OpenAI SDK stays in one module. Diagnostics log into a throwaway database and never count in cost per trip.
16. **Benchmark scenario** spreads trips across `kedarnath` and `sikkim` (SPEC 10.2); all SOS happen on the Kedarnath trail. Notes are in English, Hindi and Assamese. Regenerate with `scripts/make_benchmark_scenario.py` (deterministic).
17. **Benchmark runs in its own database** (`backend/benchmark.db`), so demo screens never show benchmark trips. SOS are replayed through the real grouping code; cluster summaries follow the app's refresh limits in scenario time (one per `CLUSTER_SUMMARY_MIN_INTERVAL_S`, at most 3); R1 re-summarises after every SOS; copilot is one brief per incident. Each run tags its Prune run ids (`_b<run>`) so step and budget guards never carry over between runs.
18. **Benchmark overrides go through a context variable** (`ai/jobs.py::BENCH`: nonce, policy, cache, forced tier, naive = no governor and no run-budget header). The live app never sets it, so feature code has no benchmark branches.
19. **Cluster summaries now flag Prune injection signals** on the incident, the same way single reports already did, so a suspicious note inside a cluster is flagged too.
20. **The injection scanner is English pattern matching.** The benchmark shows it catches the English tricks and misses Hindi and Assamese ones; those rely on Prune's injection detection. Don't claim more than that.
21. **Extra routes `sikkim` (Lachung to Yumthang) and `park` (Dhangarhi gate to Dhikala, Corbett Tiger Reserve)** are built by `scripts/make_extra_routes.py` from hand-placed waypoints, because OpenStreetMap wasn't reachable from the build machine. Lines are approximate and every help point, checkpoint and zone is labelled simulated. Redraw the waypoints (geojson.io) or extend `fetch_osm.py` for real geometry.
22. **Template files can be partial:** any string missing from a language file falls back to English (`seeddata.templates`). `ne.json` (Nepali, for Sikkim) has only the phrasebook so far and is marked machine-translated.
23. **The responder's route picker lists every seeded route** from `/api/routes`, so adding a route file is all it takes.
24. **SMS inbound** (`app/sms.py`, `POST /api/sms/inbound` with a shared secret): the app's coded SOS SMS is parsed by a regex (no AI) and deduplicated against the same SOS sent over data, by the first 8 characters of its id, in both directions. Free text from a phone number registered on an active trip becomes an SOS immediately (kind unknown, flagged "Call back"), at the trip's last known position. Then the `sms_parse` AI job ($0.003, SMALL) may fill in only fields that are still unknown, never if that would lower the rules-based priority, and may only quote a place that is written in the SMS. Texts from unknown numbers are never dropped: they go to responders as call-back requests. The sender's number is never stored (salted hash + last 4 digits); SMS text is cleared after 30 days. Coded times are read as Indian time.
25. **Phase 2 Digital Tourist ID is built, simulated** (`app/permits.py`, SPEC 17): a mock registry with fake numbers; the ID number is normalised, looked up and hashed at once (only the hash and last 4 characters are stored, and neither the number nor the last 4 go into the event chain or any prompt); upgrading re-signs the pass with permit type, dates and `permitted_zone_ids`; restricted zones not in that list alert "Not permitted for your pass" on the phone and show "Not permitted for this area" at checkpoints; revocations sync to checkpoint devices for offline refusal; lookups are limited to 10 per trip per hour. Aadhaar is optional, last 4 digits only, `self_declared`, never a permit. The permit card is a Prune feature (`permit`, SMALL, $0.004) cached per (state, permit type, language), with the official text as its standard text. **Not built:** the optional OCR photo check (tesseract.js) from SPEC 17.2 step 3.
26. **Cost attribution:** `sms_parse` counts toward cost per emergency, `permit` toward cost per monitored trip.
27. **Projector extras:** a headline counter (round, people on the trail, SOS → incidents, AI cost this round from Prune's own figures, "standard text (no key)" when AI is off, never a guessed number); confetti plus a synthesised cheer when an incident is accepted (sound only after a tap on the speaker icon, no confetti with reduced motion); **Next round** on Stage control: one tap with a 3-second cancel window recaps the round from database rows (`DemoState` "round"), resets the demo and publishes `stage.round`. `/ai/stats` accepts `since` for per-round cost.
28. **Prune's `exact` cache needs two guards** (`prune_client.py`: `case_tagged` and `X-Prune-Max-Cache-Error: 0`). On its own, `X-Prune-Cache: exact` returned one incident's summary for another, which is what SPEC's "always exact" rule is there to stop. On the real `cluster_messages` prompt, changing the people count, injuries, place, time span, emergency kind or note each returned the first incident's answer. Two layers cause it: the template cache (`template_semantic`) matches on the system prompt, and the semantic layer (`semantic_verified`) matches similar text. The strict header alone left the first, and a fingerprint of the request in the system prompt alone left the second. With both, all six changes were misses with the right facts, advisories kept their own language and place, and a true repeat was a real `exact` hit, also through the real SOS and Next round code. `prune_check.py`'s `cache_safety` check fails if this stops holding, and `PRUNE_CACHE_MODE=off` turns the cache off. A nonce in the user message doesn't stop these matches; the benchmark's nonce is in the system prompt, so it changes the fingerprint.
29. **The provider is Gemini for now:** `MODEL_SMALL=gemini/gemini-3.1-flash-lite` (no thinking) and `MODEL_LARGE=gemini/gemini-3.5-flash` (thinks first; Google serves it as `gemini-3.6-flash`). The 2.0 and 2.5 models return 404 for new users, and `gemini-3.1-pro-preview` returned 429 on the free key. The free key is unreliable: in one full run, 5 of 16 calls returned 503 and 3 timed out. Hardik chose to keep it for the demo, so expect some standard text on stage; `docs/DEMO_SCRIPT.md` covers it.
30. **Prune answers Gemini models in Google's own shape** (`candidates`, `usageMetadata`, `modelVersion`), even on `/chat/completions` through the OpenAI SDK, so `prune_client.py` reads both shapes. Before this, every Gemini reply read as empty text with no error, and `prune_check.py`'s `app_path` check still said OK. It now fails on an empty reply.
31. **Token room.** Gemini 3.5 Flash spent 641 to 1,299 tokens thinking before a 115-token summary, and that counts against `max_tokens`, so `chat()` adds `LARGE_THINKING_TOKENS` (2000) on the large tier. The safety pack is about 1,000 tokens long, so its limit went from 900 to 1600. Its budget went from $0.01 to $0.03: with $0.01, Prune stopped even a tiny second call after one pack that it reported as $0.0013, so a repair could never run.
32. **Standard text first, longer AI timeouts.** `build_report` and `build_cluster_summary` now save and publish the template before calling the AI, which is what SPEC describes for the report but wasn't built. That makes it safe to raise the job timeout to 45 s (SPEC says 20 s, and 8 s for the report): a Prune call takes about 5 to 7 s before the model starts, and Gemini added 1 to 32 s more. `/trips/{id}/permit-card` keeps 20 s because a tourist's screen waits on it, so on a slow day that card can fall back to standard text.
33. **Every AI job gets its own Prune run id** (a random suffix added in `run_job`). Prune remembers a run for good: a run stopped for budget stays stopped, and repeating a payload under a used id gets 429 `agent_loop`. Incident numbers restart after a reset and a pack keeps one job key, so ids would collide.
34. **`reset_demo` also deletes incident AI jobs** (`inc_`, `clu_`, `cop_`). Jobs are keyed by incident number and numbers restart after a reset, so a kept job gave a new incident the previous round's AI report. `next_round` calls `reset_demo`, so this would have happened between judging rounds. It stayed hidden until the AI was live, because template jobs are never reused.
35. **Prune's Gemini costs are unverified.** Across 20 live calls, the reported cost fits Prune's own estimate of the input tokens times a flat price, with output ignored: about $1.50 per million for `gemini-3.1-flash-lite` and $0.15 for `gemini-3.5-flash`. So a pack costs `0.001266` at both 896 and 1,103 output tokens, and the small model looks ten times dearer than the large one. `gemini-3.1-flash-lite` isn't on the three-model Gemini price list in Prune's vault screen. The run budget (31) also behaves as if far more was spent. The app still shows Prune's numbers, as the rules say, but check them against Google's own usage page before quoting them on the cost slide. `LlmCall` stores the real token counts.
36. **A map failure only loses the map** (`MapView.tsx`). With no WebGL, MapLibre throws while starting, which blanked the whole screen, SOS button included. The map now shows a message instead, and zone alerts and SOS keep working. Confirmed by playing the full demo with WebGL off.
37. **`/jr` shows the Timeline tab**, because `docs/DEMO_SCRIPT.md` has the judge tap **Verify timeline** there and the tab was hidden.
38. **Group summary numbers stay exact.** AI summaries still run at most once a minute, but an SOS during that wait now shows standard text with the right counts at once, and a fresh AI summary follows when the wait ends. Before, nothing came back to update it, so the card could say 4 people next to a count of 12. AI text written for older counts is dropped.
39. **Break it limits fit a full room:** 60 attempts per network per hour (it was 15), cleared on reset and **Next round**. On venue Wi-Fi or behind the tunnel every judge shares one address, so the old limit could lock out the room and stay locked for later rounds. The limit of 3 per device stays.
40. **The app keeps the public key on the small model** (`jobs.run_job`), including group summaries and escalations, which would otherwise ask for the large model. SPEC relies on an allowlist in Prune's dashboard, which lives under Shield and we couldn't set. The app's check needs no dashboard setting and works on every laptop. The key is server-side, so judges can't reach Prune with it directly.
41. **The demo venue is the CSED block.** The route id stays `hall` so nothing else changes, and the name shown is "CSED block". `DEMO_ZONE_RADIUS_M` is now 75: the farthest point of the loop is 38 m from its centre, and indoor GPS can be off by 30 m. The whole loop sits inside the zone, which is fine because **Show safe way back** points 20 m past the zone's nearest edge. It's a straight line, so it can cross a wall: present it as a direction, not a walking route.
42. **When a model is busy or out of quota, the job tries the other one.** The free key ran out of `gemini-3.5-flash` quota during the benchmark while `gemini-3.1-flash-lite` kept working, and group summaries were falling back to standard text. A job that fails on the large model now retries on the small one. Budget stops never do this. Prune's own error `code` is now read properly: the SDK dropped it, so Google's quota error looked like a Prune rate limit and paused all AI for 20 seconds.
43. **The budget stress test really stops.** It skips the cache, because a cached answer arrives before Prune's budget stop runs, and a later refresh no longer replaces the standard text until a new SOS changes the numbers.
44. **The costs we quote come from tokens, not from Prune.** Prune's Gemini cost leaves out output tokens (35), and a free key has no bill to check against. So `docs/BENCHMARK.md` works cost out from Google's token counts at Google's list price: about 3 paise per trip and 10 paise per emergency on a first day. Prune's total for the same run is close, but it splits differently (2.4 paise per trip, 15.2 per emergency), because it prices input at a flat $1.50 per million and skips output. The recorded run used 100 trips and the small model throughout, because the free key's `gemini-3.5-flash` quota ran out, so R1 is a low estimate.
45. **The deck's chart is plain shapes.** Keynote and Quick Look draw every pptxgenjs chart blank, even a bare one, and Hardik's Mac has Keynote, not PowerPoint. Shapes stay editable and show everywhere.
46. **Line icons instead of emoji** (`frontend/src/components/icons.tsx`, lucide): SOS kinds, zone kinds, weather and warnings. Emoji look different on every phone and read as playful on an emergency screen; line icons take the text colour. Map markers use the same icons as inline SVG.
47. **Terrain relief on the map:** a MapLibre hillshade from the open AWS Terrain Tiles (Mapzen "terrarium" elevation, no key, about 30 m detail, source `maxzoom` 12) over the OpenStreetMap tiles, softer when zoomed in. The service worker keeps viewed elevation tiles for 30 days (`terrain-tiles` cache), so ridges and valleys still show without signal.
48. **Map layers are added on `style.load`, not `load`.** MapLibre's `load` waits for every tile, and when tiles failed (a weak or missing connection) it sometimes never fired: the map then showed no route, zones or help points at all. Found while testing with map tiles blocked.
49. **Zone outlines are true buffers.** `fetch_osm.corridor` used a plain left/right offset, which folds over itself on switchbacks; the even-odd point-in-polygon test then read the folds as holes (3% of the Kedarnath landslide section and 6% of the old road tested as outside their own zone). It now traces the distance contour (marching squares, pure Python), keeps the outer ring (pockets between switchbacks count as inside) and errs a few metres outward, never inward. `scripts/rebuild_zone_outlines.py` redrew the seeded outlines without internet; each corridor zone now keeps its `centerline` and `half_width_m`. A test checks that every seeded outline is simple and contains its own line. The demo group now stands together in the middle of the zone, so their SOS still form one incident.
50. **The tourist map shows only the compass, not the zoom buttons.** The top bar's "Online" chip sat on top of the zoom buttons, so they couldn't be tapped. Phones pinch to zoom; the compass now fits beside the top bar. The responder map keeps its zoom buttons.
51. **The app wears the deck's design.** Warm charcoal and paper, Barlow Condensed headings, Inter body text, the deck's teal, gold, purple and red, and its colour dots on a dashed gold line. Colours live in `tailwind.config.js`, so every screen changed together. The fonts now ship inside the app (`@fontsource`), so they work offline and the app no longer calls Google Fonts. The responder's incident panel shows the deck's five steps, live. No feature was removed.
52. **One-tap CSED red zone.** A new zone kind, `red_zone`, with its own wording in English and Hindi. `POST /stage/csed` works for responders and the presenter and uses the same `publish_zone` path as a drawn zone, so it reaches phones, the event log and the AI warnings the same way. The zone is the `hall` loop plus 20 m on each side, because GPS near a building drifts. A second tap changes nothing. It stays labelled simulated.
53. **The crowd is a heatmap, like Google Maps' busy areas.** The crowd engine now also counts people on a 6 m grid, and the map draws that as a soft glow from green to red, instead of 25 m boxes. Automatic crowd zones and their warnings work as before, but draw as heat only, with no outline or badge. Tourists' phones get the heat too, only for spots with 3 or more people, so nobody's position shows alone. The heat clears when people leave, which it didn't always do before.
54. **The simulated crowd covers one area.** "Simulate crowd" puts 80 simulated people around the CSED block only, at the doors and paths, for 5 minutes. The older "Crowd surge" button is unchanged. The map labels this crowd "Simulated".
55. **A simulated walk for when GPS won't play along.** On the `hall` route the trip screen has "Simulate walking into CSED". It feeds fixes into the same on-phone geofence as real GPS, so the approach warning and the alert are the real ones and only the position is simulated, which the screen says. It resets the geofence first, so a second take alerts again.
56. **A crowd alert shows once in 5 minutes and never covers a danger alert.** A crowd can shift into several zones, which would otherwise fire several full-screen alerts in a row.
57. **Live updates also arrive by a 2-second fetch.** Free Cloudflare tunnels hold back event streams: in a test, nothing came through in 11 seconds, not even the first message, so a flagged zone or "Help acknowledged" never reached a phone on the tunnel. Every event now has a number, `GET /api/events/poll` returns anything after a given number, and every screen asks every 2 seconds alongside the stream. Each event is handled once. The checks at phones and the responder now run through the real tunnel.
58. **Not deployed on Vercel.** Vercel can host the screens, but not the server. SafeTrail needs one always-on process: the SQLite database, the live event stream to phones, and the background crowd and quiet-tourist loops. Vercel runs short-lived functions that don't share memory or disk, so an SOS could reach one instance and never show at the responder. Moving it would mean rewriting the backend right before judging. `scripts/run_phones.sh` gives one public https link from the laptop instead.
